# Sponsor and event constraints checked during bootstrap

These are observed requirements, not an eligibility decision. Re-fetch before qualification.
Classic excludes prior project-specific work; Continuity permits declared existing work subject
to track rules. Event requires incremental Git history, transparent reuse/AI assistance and
spec-driven planning/prompt artifacts. Event demo is 2–4 minutes.[1]

Hedera AI & Agentic Payments requires a live x402-gated service on Hedera testnet/mainnet settled
through Blocky402, an actual consuming paid request, and public source/setup/payment-flow docs.
A generic simulated payment is not enough.[2]

ENS prize requires ENSv2 on Sepolia, central product functionality and a functional non-hardcoded
demo. The Continuity integration pool is distinct. Plain ENSv1 name lookup is insufficient.[3]

Graph AI tooling/use-case pools distinguish from-scratch and Continuity, require live Graph-provider
data, meaningful decisions/tooling rather than raw query printing, reusable infrastructure for tooling
submissions, and public source/README or SKILL.md. Local/static/mock data does not qualify.[4]

Keep app scope bounded: meaningful provider selection via Graph, ENSv2 delegated service records,
and real Blocky402 paid request. Extra sponsor features are not mandatory core work.

Sources block is generated from docs/sources.json.
